Motivation & Background

Code that reads as correct is not code that is correct

  • FinPilot is a multi-tenant MERN finance platform — workspaces own accounts, transactions, budgets, goals, debts, investments.15 feature modules, background jobs, Docker, Redis — it looked finished.
  • It had never been exercised end to end.Completeness of surface hid a non-functional core.
  • Fast-built and AI-assisted code fails semantically, not syntactically — a wrong field name, an uncast type, a stale API.Such errors pass code review and surface only on execution.
The premise
A finance app is judged first on whether its numbers are right,
then on whether it stays right as data grows. This study tests both — empirically.

The finding that framed everything

The dashboard reported zero. Ground truth was ₹50.5 crore.

// dashboard.service.js — as shipped
Transaction.aggregate([
  { $match: { workspace: "abc…" } }, ← string
  { $group: { _id: "$type",
    total: { $sum: "$amount" } } } ← no such field
])
→ returns [] ⟹ income 0 / expense 0
  • aggregate() does not cast a string id to ObjectId the way find() does — 0 documents matched.
  • The field is money.amount, not amount — the sum totalled a missing field.
  • Two independent bugs stacked. A test asserting only "responds 200" passes against this.
  • The same pattern recurred in 12 pipelines across five services.

Discussion · the methodological core

Each experiment caught a wrong version of itself

E2Correctness gateThe broken pipeline would have won — fast because it computed nothing. Gate: match ground truth before timing.
E3Plan assertionDropping one index silently fell back to another. Gate: assert IXSCAN vs COLLSCAN is what the variant claims.
E4Sort assertionAn uncovered cursor key made cursor look slower. Gate: fail if any plan holds a blocking SORT.
In an analytics system, correctness must gate performance — a benchmark that skips this rewards the implementation that computes nothing, because computing nothing is fast.
